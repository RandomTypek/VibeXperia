# LineageOS 16.0 (Android 9 / Pie) bring-up notes — Sony Xperia M (`nicki`)

Forward-port of the [15.1 port](README.md) to Android 9. The kernel and graphics
blobs carry over from 15.1; this documents the Pie-specific work. Blow-by-blow,
newest-relevant first.

## Build walls (in order hit & cleared)

1. **Product discovery** — Pie dropped `add_lunch_combo`; added
   `device/sony/nicki/AndroidProducts.mk` (`PRODUCT_MAKEFILES := lineage_nicki:$(LOCAL_DIR)/lineage.mk`).
2. **Audio kernel headers** — `hardware/qcom/audio-caf/msm8960/hal/Android.mk`
   re-set `LOCAL_HEADER_LIBRARIES :=` in the same module block, clobbering
   `generated_kernel_headers` → `sound/msmcal-hwdep.h` not found. Changed the 2nd
   assignment to `+=`. (`patches/android_hardware_qcom_audio-caf_msm8960.patch`)
3. **sepolicy** — removed Pie-dropped types (`camera_socket`, `mpdecision`),
   fixed 8 neverallow build-asserts (`sysfs_type`→`fs_type` for the sysfs led
   nodes, `data_file_type`/`core_data_file_type` on /data types, isolated_app
   sysfs, dac_override). (in the device tree)
4. **kernel `O_TMPFILE`** — the 3.4 asm-generic `fcntl.h` shadowed bionic's;
   backported `O_TMPFILE`. (kernel repo)
5. **webview** — LFS pointer apks; pulled the real prebuilts.

## Runtime blockers (in order)

- **Recovery "wipe data" no-op** — `bootable/recovery/roots.cpp` aborted
  `format_volume()` when the crypto `key_loc` (`/persist/footer`) was unreachable
  in recovery. Made that non-fatal so `mke2fs` still runs.
  (`patches/android_bootable_recovery.patch`)
- **No adb in recovery / booted** — Pie adbd is FunctionFS-only; nicki's 3.4
  kernel has the legacy in-kernel `/dev/android_adb` gadget. Ported the 15.1
  runtime-probe adbd patch. (`patches/android_system_core.patch`)
- **Boot stall — missing `vendor.lineage.power@1.0` HAL** — manifest declared it
  but the service was disabled → framework blocked forever in
  `ILineagePower::getService()`. Re-enabled the service (device tree).
- **Black display (SurfaceFlinger back-pressure)** — the msm8960
  HWC1-via-`HWC2On1Adapter` reports `PresentFenceIsNotReliable`; the present
  fence never signals → `SurfaceFlinger::onMessageReceived(INVALIDATE)` sees
  `frameMissed` forever and skips compositing after the first frame. Set
  `debug.sf.disable_backpressure=1` (`product/display.mk`).
- **Popup / notification-shade / scroll freeze (~10 s)** — with back-pressure
  disabled, SF's own framebuffer output starved: `FramebufferSurface::onFrameCommitted()`
  attached the unreliable present fence as the FB buffer's release fence, so the
  buffer never freed and SF blocked in `msm_fb_pan_idle`/`sync_fence_wait` on any
  sustained buffer cycling (`DequeueBufferDuration=9.9 s`). Static surfaces
  (keyguard) hid it. Fix: skip that fence (`NO_FENCE`) when the HWC reports
  `PresentFenceIsNotReliable`; the client-target acquire fence (a real GPU fence)
  is kept for client-composited layers. 99th-pct frame 4950 ms → 129 ms.
  (`patches/android_frameworks_native.patch`)
- **Wi-Fi HAL couldn't bring wlan0 up** — `android.hardware.wifi@1.0-service`
  (`user wifi`, `capabilities NET_ADMIN`) ran with `CapEff=0`: the kernel's
  ambient-cap backport zeroed `pA'` on a non-root exec (`commoncap.c`
  intersected ambient with the freshly file-recomputed, empty permitted before
  folding it in). Fixed in the kernel repo (bound ambient by inheritable only).
- **Wi-Fi supplicant configs not seeded** — Pie no longer seeds
  `/data/misc/wifi/{wpa_supplicant,p2p_supplicant}.conf`; wpa_supplicant exited on
  the missing `-c` file → `ISupplicant` never registered. Added an
  `on post-fs-data` seed from the vendor template (`rootdir/init.target.rc`).
- **Wi-Fi signal bars missing** — wificond's `GetStationInfo()` returned false
  when `NL80211_RATE_INFO_BITRATE32` was absent; the old prima driver only
  reports the legacy 16-bit `NL80211_RATE_INFO_BITRATE` → every signal poll was
  "invalid" → RSSI stuck at −127. Added the 16-bit fallback and made bitrate
  non-fatal. (`patches/android_system_connectivity_wificond.patch`)
- **rild crash-loop** — a stale `libril.so` blob (52 KB, no `ril_service_name`)
  in `system/lib` shadowed the built CAF `libril.so` (236 KB). Removed the copy
  from `nicki-vendor.mk`. **Gotcha:** removing a `PRODUCT_COPY_FILES` entry does
  **not** delete the already-installed file from `out/` — `rm` it (or
  `make installclean`) or the OTA keeps shipping the stale artifact.
  (`patches/vendor_sony_nicki.patch`)
- **Bluetooth HAL crash-loop** — passthrough `@1.0-impl` aborts on Pie
  (in-process `linkToDeath`). Switched to the binderized
  `android.hardware.bluetooth@1.0-service` + `hwbinder` manifest entry, and
  published the controller BD_ADDR to `persist.service.bdroid.bdaddr` from
  `init.qcom.bt_mac.sh` (the HAL only reads the ASCII prop, not the binary NV).

## Known-broken / TODO

- **Bluetooth radio** — HAL/service are stable and the stack starts, but the
  controller (WCN2243 pronto over SMD) rejects a vendor controller-init HCI
  command (`read_command_complete_header: return status - 0x1`), never programs
  the BD_ADDR (adapter reports `00:00:00:00:5A:AD`), so the framework times out
  (`waitForOnOff`) and restarts every ~8 s. Deep vendor/firmware bring-up.
  (Non-fatal aside: `timer_create(CLOCK_BOOTTIME_ALARM)` returns ENOTSUPP — the
  3.4 kernel lacks posix-timer support for alarm clocks; bt_osi falls back.)
- **Camera** — 0 devices; the four HAL1 `CameraDevice.cpp` fixes from 15.1 are
  not yet ported.
- **Diagnostics to strip before release** — `init.target.rc` still force-enables
  adb (`setprop sys.usb.config adb` in `on boot` + a `sys.usb.config=none`
  re-assert) and writes `/cache/nboot_*` boot tracers.
- **SELinux** — permissive (parked).
